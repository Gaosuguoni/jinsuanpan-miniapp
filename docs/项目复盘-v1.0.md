## 一、一句话定位

**金算盘是一个面向个体户商贩的语音记账微信小程序：不用学、不用打字，按住说一句话就把账记下，并自动算出金额、报出日结。**

---

## 二、用户与痛点

**用户**：个体户商贩，**以菜摊、水果摊为主**（其次是小吃摊、夫妻店这类"一人或夫妻经营、没有专门财务"的生意）

**待验证的假设（不是结论）**：以下痛点来自公开讨论与个人判断，**尚未经过真实用户访谈验证**，这正是接下来试点要确认的第一件事。

1. **糊涂账**：进货、卖货、损耗、日常开销混在一起，月底不知道自己到底赚了多少；
2. **生鲜损耗记不清**：菜和水果卖不完会烂，损耗多少没数，直接吃掉利润（对菜摊、水果摊尤其致命）；
3. **忙时没时间记**：手上有活、手是脏的，腾不出手打字；一忙起来干脆就忘了记。

**第 4 个假设（两种"赊"都要单独验证）**：

| 方向 | 假设 | 说明 |
|---|---|---|
| 面向顾客 | 菜摊/水果摊**赊账可能并不普遍** | 顾客流动、金额小、扫码付款方便；老顾客挂账可能存在但频率未知 |
| 面向上游 | 进货"先拿货、卖完再结"的**账期可能更常见** | 批发市场拿货常见先拿货后结；若成立，产品重心应偏向"我欠谁多少/这个月结清了吗" |

**由此推出的产品原则**：**入口必须极简**——不用注册流程、不用学操作、不用打字，最好是"按住说一句话"就完成记账。

> **如何验证**：走访时问 4 个问题——① 有熟客赊账吗？② 多久一次、一次多少钱？③ 怎么记的（脑子/本子/手机）？④ 最怕什么？
> 若验证发现赊账并不普遍（例如菜摊对陌生顾客），产品重心将转向「日结 / 毛利 / 进货对账」，而不是硬做赊账功能。

## 三、我做了什么

### 技术链路

```
微信小程序（按住说话 / 打字）
  → 录音上传云存储
  → 云函数 asr 调用腾讯云一句话识别（ASR）
  → 确定性记账引擎解析成结构化数据（类型/品名/数量/单价/总额）
  → 复述确认（"记：进货 苹果 50斤 × 3.2 = 160 元，对吗？"）
  → 用户确认 → 云函数 record 服务端二次校验并落库
  → 今日流水 + 今日/本月日结
```

### 已实现的功能

| 功能 | 说明 |
|---|---|
| 按住说话记账 | 松开后自动识别并解析，不用打字 |
| 一句话多笔 | "卖白菜20斤3块、卖苹果10斤5块" 自动拆成两笔 |
| 复述确认 | 落账前把结果念/显示一遍，用户确认后才记账 |
| 六种账目类型 | 进货 / 卖货 / 赊账 / 收款 / 支出 / 损耗 |
| 今日与本月日结 | 营业额、现金收入/支出、净现金、参考毛利、累计未收 |
| 可撤销 | 任何一笔都能删除 |
| 双模式运行 | 云开发模式；未配置云环境时自动降级为本地演示模式 |

### 工程细节（做了什么"看不见但重要"的事）

- **金额永远由确定性引擎计算**，语音识别只负责"填字段"，模型/识别不碰数字；
- **服务端二次校验**：客户端传的金额不被信任，云端 `validateForSave` 重新计算；
- **识别双通道容错**：优先用云存储临时 URL 交给 ASR，失败自动回落 base64 直传；
- **环境变量白名单校验**：配置填错时自动回退默认值，不让用户卡死；
- **每人每天限次**（默认 50 次，可配置），防止恶意刷量；
- **隐私与成本**：录音识别完成后立即删除；密钥只存在服务端，客户端代码里没有任何密钥；
- **66 个单元测试**覆盖解析、金额计算、汇总口径。

## 四、关键决策与理由

| 决策 | 为什么这么做 |
|---|---|
| 用微信小程序，而不是独立 App | 商贩的世界就是微信，不用下载安装、不用注册新账号，扫码即用 |
| 语音优先，打字作为备用 | 忙时手上是脏的/腾不出手；语音是唯一"零学习成本"的入口 |
| 金额必须由确定性引擎算，识别只填字段 | 账算错一次，用户就再也不信了；AI 只做"听懂"，不做"算钱" |
| 服务端再算一遍 | 客户端可能被改、可能出错；服务端重算是最后一道保险 |
| 放弃"同声传译插件"，改用自带录音 + 云函数 ASR | 插件对小程序类目/主体有要求，加不上；自带录音无依赖，还方便以后换方言模型 |
| 不向用户收费、先验证使用 | 商贩付费意愿低、客单价低；先验证"愿不愿意天天用"，再谈变现 |

## 六、踩过的坑（每个都是一次真实排错）

| 问题 | 原因 | 解决 |
|---|---|---|
| 插件"未授权使用" | 同声传译插件对小程序服务类目/主体有要求 | 放弃插件，改用自带录音 + 云函数 ASR（Plan B） |
| `need param 'Url'` / `should be uint64` | 腾讯云 ASR 的 `SourceType` 语义理解反了 | 实测确认 **0 = 语音URL、1 = 语音数据**，并用数字而非字符串传参 |
| `Not support[EngineModelType: ...]` | 环境变量被误填成文档表格文字 | 加白名单校验 + 自动回退默认值 |
| 小程序 WXSS 编译报错 | 文件带了 BOM 字符 | 全工程统一去掉 BOM |
| Git 报 dubious ownership | 仓库由另一个系统账号创建 | 配置 `safe.directory` 例外 |

> "我做的是一个给个体户商贩用的语音记账小程序。起因是这类商贩记账很麻烦：忙起来没空打字，赊账容易忘，月底不知道自己赚了多少。
> 我把它做成了'按住说一句话就记好'——录音上传，调用腾讯云的语音识别，再用一套我自己写的确定性引擎把这句话解析成'进货 苹果 50斤 × 3.2 = 160 元'，然后念给用户确认，确认后才落账。
> 里面最关键的一个设计是：**金额永远由代码算，识别只负责填字段**，而且服务端会再算一遍——因为账算错一次，用户就再也不信了。
> 目前功能已经全部跑通、66 个测试通过、代码开源在 GitHub；真实商户试点还没开始，这是我接下来最重要的一步。"
